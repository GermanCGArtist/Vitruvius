# M2 manual test checklist (WP 2.1 to 2.3: gizmo, rotate ring, typed transforms, snapping, pivots, box select, local view)

Setup: as M1.md (Minecraft 26.1.1, Fabric, Litematica 0.27.14, a project with 4 or more objects of different sizes, some next to each other, one array, one local assembly and, if you have one, one linked assembly). Run M1.md first. Anything that fails: note what you did, what you expected and what happened.

## Move gizmo (Move tool, G or the toolbar)
- [ ] Select an object, click Move (or press G once with nothing selected; it only switches the tool). Three arrows (X red, Y green, Z blue) and a green parallelogram between X and Z sit on the pivot. Walk the camera far away and close: the gizmo stays the same size on screen.
- [ ] Hover an arrow: it gets thicker and lighter, the cursor is a hand, the status bar says "move along the axis". Hover the plane handle: it brightens, cursor is the 4-way arrow.
- [ ] Look straight along one axis (for example from the south along Z): that arrow fades to 25 % and cannot be grabbed. Look at the object from the side with pitch near 0: the plane handle disappears.
- [ ] Drag the X arrow: the real placement does NOT move. A dashed teal box (visible through walls) shows the new position, a thin line joins the old and new centre, the old outline is faint. The HUD under the toolbar says "Move X +n blocks". Whole blocks only. Release: the placement jumps, one Ctrl Z puts it back.
- [ ] Drag the plane handle: the object slides on the ground; HUD "Move XZ +4, -2". Y never changes.
- [ ] While dragging, Esc cancels (nothing changes). Another drag, then a right click cancels, and the camera does not start flying.
- [ ] Select Select tool (W): the gizmo disappears. Fly with RMB or orbit with MMB: it hides while the camera moves.
- [ ] Select two objects: the gizmo sits on the median of their centres; dragging moves both by the same amount, one undo step ("Move 2 objects").
- [ ] Select a part of a linked assembly (from the tree): the gizmo is grey with "Locked" under the dot, cannot be grabbed, and G shows a warning toast. Mirror X in the toolbar is greyed out.
- [ ] Select a folder or project row: the gizmo appears for what it holds and moves all of it.

## Rotate ring (Rotate tool, R)
- [ ] Click Rotate: a green ring (about 72 px) with four diamonds is drawn around the pivot, flat in the world plane. It keeps its screen size when you zoom.
- [ ] Hover the ring: thicker and lighter, hand/4-way cursor, hints "+90° click · -90° Shift click". Click it: +90° clockwise seen from above. Shift+click: -90°. One Ctrl Z each.
- [ ] Press on the ring and drag around: the dashed ghost turns in 90° steps, a faint teal wedge shows the angle, HUD "Rotate Y +90°". Keep going past 180°: it keeps counting (270°, 360° = nothing happens). Release applies; Esc or RMB cancels.
- [ ] With two objects selected the pair turns around the pivot as one. An object that is rotated about a pivot inside a turned assembly still ends where the ghost showed.

## Pivot modes
- [ ] Toolbar Pivot dropdown: Median (middle of the selected boxes' centres), Active object (the one that is highlighted brightest in the tree: click it last), Bounding box (centre of the whole selection). The gizmo and the ring move to the new pivot at once, and always sit on a block.
- [ ] Rotate two objects 90° with Active object: the active object turns in place and the other swings around it. With Bounding box: both turn around the middle of the pair.
- [ ] The Rotate +90° / -90° / Mirror X entries in the right-click menu and the Properties window use the chosen pivot too.
- [ ] Restart the game: Snap and Pivot are remembered (config/vitruvius/editor-ui.properties).

## Snapping
- [ ] Toolbar Snap off: drag an object next to another one, it moves freely in blocks.
- [ ] Snap on: drag toward a neighbour. Within 1.5 blocks its face jumps onto the neighbour's face (touching, or flush with the same side). The shared rectangle is filled teal with an outline, a diamond marks its centre and the label says "snapped to <name>"; the HUD says it too.
- [ ] An object far to the side (more than 1.5 blocks away in the other axes) is ignored. Your own selection is never a target. Hidden objects are not targets.
- [ ] Hold Ctrl while dragging: snapping turns off (with Snap on) or on (with Snap off). The highlight appears and vanishes live as you press and release Ctrl.
- [ ] Plane drag snaps X and Z separately.

## Typed transforms (G, R, Shift D, Alt D)
- [ ] Select an object, press G: the HUD shows "Move", chips X Y Z (X lit), an amount "+0", a blinking caret and "blocks". Type 12: "+12", the ghost shows 12 blocks along X. Press Y: the Y chip lights, the ghost moves along Y. Backspace removes digits (hold it to repeat). Minus flips the sign. Enter applies (one undo step), Esc cancels.
- [ ] Shift+Y: chips X and Z lit, amount shows "+0, +0". Type 4, comma, -2: "+4, -2". Enter moves on the plane. Shift+X and Shift+Z choose the other planes.
- [ ] Click the Z chip with the mouse while typing: the axis changes, the typed number stays. Clicking the HUD does not cancel anything.
- [ ] While dragging an arrow press a digit: the drag hands over to a typed move on that axis (the mouse stops moving the object). Esc cancels it.
- [ ] Press R: HUD "Rotate Y 0° snaps to 90°". Type 180, Enter: the object turns 180°. 100 gives 90°, 44 gives 0 (nothing happens), -90 turns the other way.
- [ ] Press Shift+D: HUD "Duplicate"; type 8, Enter: a copy appears 8 blocks along X, selected, the original stays. One Ctrl Z removes the copy and its file. Esc cancels without making a copy. Alt+D does the same as a linked duplicate (the copy shares the file).
- [ ] During any typed transform, other shortcuts (H, M, B, ...) do nothing. Clicking a row in the tree ends the typed transform without applying it. F6 while typing also cancels.
- [ ] Context menu: Move (G) on an object starts a typed move.

## Hide, show, mirror
- [ ] H hides the selection (toggles), Alt+H shows everything hidden. Ctrl Z undoes both. Hidden objects have no gizmo box.
- [ ] M mirrors X about the pivot (toolbar button too).

## Local view (/)
- [ ] Select one object, press /: every other object in your projects disappears from the world (their placements are removed from Litematica for now), the status bar starts with "Local view: leave /", the toolbar button is lit. Picking and the gizmo only see the isolated object.
- [ ] Move or rotate the isolated object: works as usual and saves. Loose (1.x) objects are NOT hidden by local view.
- [ ] Press / again (or the right-click entry "Leave local view"): everything returns, nothing is hidden in the tree, the project files did not change (check project.json is unchanged apart from your moves).
- [ ] Press / with nothing selected: a toast says to select something first.
- [ ] Switch world or leave and re-enter the game while in local view: it is off again.

## Box select (B, or drag on empty space)
- [ ] Press B (or the toolbar Box button): the cursor becomes a cross. Drag a rectangle: a teal rectangle follows, objects whose centre is inside get a faint outline live. Release: they are selected. Hidden objects are not selected; neither are parts of assemblies (the assembly is).
- [ ] Shift while releasing adds to the selection, Ctrl subtracts (the rectangle turns red). Esc cancels. A click without a drag does nothing.
- [ ] Drag from empty space (not from an object) in the Select tool: the same box select starts after about 5 px. A plain click on empty space still deselects.
- [ ] B then right click cancels.

## Performance
- [ ] Select a big schematic (millions of blocks): the Properties window shows "..." and "counting" for the block count and the game does not hitch; the number appears a moment later.
- [ ] Drag a gizmo arrow around with 20+ objects in the scene: no stutter from snapping.

## Not covered by M2 (expected)
- No array-copy ghosts while dragging (only the selected boxes), no top view, no Boolean Apply.
