# M3 + M4 manual test checklist (WP 3.1 and 4.1: arrays on assemblies, Realise, linked assemblies, exports, bake)

Setup: as M1.md (Minecraft 26.1.1, Fabric, Litematica 0.27.14). Two projects, "Metro" (active) and "Depot", each with 3 or more objects of different sizes. Run M1.md and M2.md first. Anything that fails: note what you did, what you expected and what happened.

## Arrays on assemblies (WP 3.1)
- [ ] Select 2 or 3 objects, Ctrl G. Select the assembly, Properties, "+ Array", count 3, Relative X 1.0. Every part is repeated for each cell: 3 copies of the whole group, side by side, with no gap and no overlap (the step is the width of the union of the parts).
- [ ] The overlay shows the assembly box around all three cells, and a thin outline per copy. Selecting the assembly frames all copies (F).
- [ ] Change the count to 2: the third copy disappears. Count back to 3: it comes back. Switch the array off with its toggle: only the original stays.
- [ ] Move or rotate the assembly: all copies follow (a 90° turn makes the row run along Z).
- [ ] Put an array on one part inside the assembly too (nested arrays), then on the assembly: both show, no overlaps of the copies' cells.
- [ ] Hide the assembly: original and copies vanish; show: they all come back. Local view (/) on the assembly keeps all its copies, on another object hides them.
- [ ] Restart the game, open the world: the copies of the assembly are back (their placements are runtime only, they are created again from the model).
- [ ] An array on a linked assembly (see below) works the same.

## Realise (WP 3.1)
- [ ] Right click an object with an array: Modifiers ▸ Realise array. A folder "name (realised)" holds the original and one object per copy at the right places, each with its own placement; one undo brings the array back.
- [ ] Same for an assembly with an array (Modifiers ▸ Realise array, the Properties "Realise into N objects" button or the ⋯ menu): the folder holds assembly instances. Give one of them an array again: it works, with its own size.
- [ ] A linked assembly with an array realises into linked instances of the same file.

## Add Assembly, Link project (WP 4.1)
- [ ] Right click empty space, Add ▸ Assembly…: a list of .lasm files in the active project and in schematics/ (not in Projects). Pick one: a linked assembly appears at the camera target, with the link icon in the tree and the Properties source line showing the path.
- [ ] Add ▸ Link project as assembly…: lists the other projects (open and closed). Pick "Depot": its whole content shows as one linked assembly in Metro. Project row menu "Link into active project as assembly" does the same.
- [ ] Linking a project into itself, or A into B when B links A (also through a .lasm), is refused with a toast that shows the loop.
- [ ] The same .lasm linked twice gives two independent instances (move one, the other stays).

## Create / Save as linked
- [ ] Ctrl G on a selection: a local assembly (as before). Context menu on it: Assembly ▸ Save as linked .lasm. The assembly is now linked, `files/assemblies/<name>.lasm` exists in the project folder, and nothing moved. One Ctrl Z restores the local assembly; the .lasm is in `.trash`, not gone.
- [ ] Context menu on a multi-selection: "Create linked assembly (.lasm)": one step, one undo.
- [ ] Two assemblies with the same name: the second file is "name 2.lasm".

## Linked assemblies
- [ ] Edit the source: Open the project that holds the .lasm (Assembly ▸ Open source, for a project link), change an object, save (Ctrl S). The instance in the other project updates within a few seconds. Or replace the .lasm on disk: it updates too.
- [ ] Assembly ▸ Reload from source re-reads the files at once.
- [ ] Assembly ▸ Open source: for a project link opens that project (and selects it); for a .lasm shows a toast with the full path.
- [ ] Try to move or delete a part of a linked assembly: refused with a reason ("part of the linked assembly ... Make the assembly local first"). Properties shows the lock banner.
- [ ] Assembly ▸ Make local: parts appear under it, the files were copied into the project's files/ folder; Ctrl Z undoes (copies go to .trash).
- [ ] Assembly ▸ Break up in place on a linked assembly: one step (make local and break up); the result is a folder of objects in the same places. Ctrl Z once restores the linked assembly.
- [ ] Assembly ▸ Realise (independent copies) on a local assembly: a folder of objects; each has its own copy of its file (check files/); the originals stay. On a linked one: files are copied by Make local, objects are independent.
- [ ] Delete the .lasm on disk (or rename it): the instance shows nothing, no crash; put it back: it returns.

## Exports (everything goes to schematics/exports/ with a unique name; a toast shows the path)
- [ ] Assembly ▸ Export ▸ Assembly (.zip) (also the Properties "Export .zip"): the zip holds `<name>.lasm`, `files/*.litematic`, and `files/assemblies/*.lasm` for nested linked assemblies. Unpack it into a new project folder, open that project: it looks the same. Exporting again gives "name 2.zip".
- [ ] Folder ▸ Export folder (.zip), and Export ▸ Selection (.zip) with 2 objects selected: the same shape.
- [ ] Project row ▸ Export ▸ Project (.zip): the whole project folder, without `.cache` and `.trash`.
- [ ] A missing file does not stop the export: the toast says "1 warning" and the zip simply lacks it.
- [ ] Export ▸ Schematic (.litematic) on one object: its file is copied into exports/ (the Boolean-trimmed variant comes in M5).
- [ ] Export ▸ Bake to one .litematic on an assembly with an array and a rotated part: the toast says N sub-regions. Load the file in Litematica: the sub-regions sit where the parts were relative to each other, rotated and mirrored parts have their blocks turned (stairs, doors and logs face the right way). Placed at the old minimum corner it matches the originals exactly.
- [ ] Bake a project and a multi-selection (also a linked assembly): works; a huge selection does not freeze the game (it runs in the background and the toast comes when it is done).

## Menus and buttons that were disabled before
- [ ] No entry in the Assembly, Export, Add menus, the Properties assembly/project/folder bodies or the ⋯ menu of the array card says "Coming in a later 2.0 alpha" any more (Apply Boolean, Heavymatica, Syncmatica and the Top view still do).
