# M6 test sheet: per-cell trims, Top view, Syncmatica, object-type API v2

Unit tests cover the pure parts (see the end). Everything below needs the game. Minecraft 26.1.1, Litematica 0.27.14.
Do not launch from the build: the architect installs the jar.

## 1. Per-cell trims (needs two overlapping objects)

1. Project with object A (front 1) and B (front 2). Give B an array of 4 so some copies overlap A and some do not.
   Within about a second the status bar shows "Rebuilding n derived files..." and only the overlapping copies lose blocks.
   `Projects/<name>/.cache/derived/<B id>-<hash>.litematic`: one file per different mask; copies that sit the same way
   relative to the things trimming them share one file (check the file count against the number of distinct overlaps).
2. Drag A with the gizmo: no rebuild until release. After release every affected copy of B switches file.
3. Loose: give a Loose object a front order (PgUp) and overlap it with a numbered project object that has a better front: it is
   trimmed (its placement is replaced by the derived file, same hash id). An unnumbered winner never trims a Loose object.
4. Linked assembly: link an assembly (with two parts that overlap an object of better front): the parts are trimmed per cell.
5. Cap: make an array of 300 copies each overlapping a differently placed winner (a staircase of winners is enough). After the
   rebuild the status bar says "1 object has more than 256 trim variants: n copies keep the original file". The first 256
   copies are trimmed, the rest show the original file. Reduce the array: the warning goes away.
6. Save the project: unused derived files move to `.trash/derived`; none is deleted. Loose derived files live in
   `config/schemarray/editor-loose/.cache/derived` and are not cleaned up.

## 2. Top view

1. Windows menu (toolbar) or the map icon next to it: Top view opens under Properties (it starts closed when the screen is lower than 620 px).
2. Objects show as filled rects (array copies fainter), the selection in teal, overlaps red with a hatch, areas of other mods
   with a long-dash amber outline, wire cutters dotted violet. The camera is a dot with a wedge, the orbit target a ring, the player (when away from the camera) a teal dot.
3. Middle or right drag pans, the wheel zooms around the cursor, "Fit" frames everything, "Follow" centres the camera. The header
   text reads "1 px = N blocks".
4. Click an object: selects it (Shift adds). Click empty map: the camera target moves there (the camera glides; in spectator the player follows).
5. Drag a selected object: a dashed ghost follows in whole blocks and a "+dx, +dz" label; release makes ONE Move (Ctrl Z undoes it
   all). Esc while dragging cancels. A selection that is locked (inside a linked assembly) cannot be dragged.

## 3. Syncmatica (needs a server with Syncmatica, 0.3.20; two clients to test receive)

Without the mod: no Push button, no Share/Push menu entries, no "Shared projects" in the Open project picker.

1. Project menu > "Share on Syncmatica" (Properties has Share / Stop sharing too). The toolbar Push button shows a pill with the
   number of pending changes (cells plus 1 for the manifest) and the status bar says "n changes not pushed". Nothing uploads.
2. Press Push: the button reads "Pushing 3/12"; every visible cell becomes a Syncmatica placement (derived file where one applies),
   then the manifest placement "[LA2] <project>" (1x1x1 air, visible in Syncmatica's list). The pill goes to 0 and the toast says
   how many placements were pushed. `project.json` now has `syncmatica` with the placement ids.
3. Move a cell, push again: only the changed cell is replaced (its Litematica placement is dropped and recreated once, then shared;
   the old server placement is removed) and the manifest is replaced (the old one removed). Delete an object: its placement is removed on the next push.
4. Disconnect while pushing: the push stops with an error toast; reconnect and press Push to continue (what was done stays recorded).
5. Second client, Open project...: "Shared projects (Syncmatica)" lists the manifest. Click it: the manifest and the base file of
   every object download, a new project appears in `schematics/Projects` (files copied into `files/`, arrays and modifiers from
   the manifest). Objects whose placement is not on the server are counted in the toast.
6. Known unverified points (not testable without a server): that Syncmatica's own move tracking leaves our reconciler moves alone;
   see "State of Syncmatica" in the milestone notes of EDITOR-2.0.md.

## 4. Object-type API v2

Needs a test mod (or Heavymatica's `2.0-api` branch) that calls `SchematicArrayApi.registerObjectType`. See API-v2.md.

1. Add menu (Shift A): one entry per registered type. Click: a new object at the camera target, selected, outline drawn by the type.
2. Properties shows the type's section; editing a field is one undo step (typing in one field keeps merging into one step).
3. Move, rotate (90 degree steps), mirror, duplicate, hide, delete, undo and redo work. Add an Array: copies are drawn (the type's
   outline is called once per copy) and appear in the Top view.
4. Boolean is refused on the object ("takes arrays only"); it never appears in overlaps, issues or the front order.
5. `objectsOfType(id)` from the test mod returns one view per copy with the world transform.
6. Remove the test mod and reopen the project: the node is grey with a MOD badge, can be moved/hidden/deleted, and saving keeps its `data` unchanged.
7. A mod that uses the 1.x `registerListEntries`: its rows show under Loose in the Scene window, dimmed, tagged "1.x" or "1.x hidden", read-only.

## Unit tests (run by the build)

`CellMasksTest` (per-cell masks, dedupe by hash, the 256 cap, Loose rule, position-independent hash), `TopViewMathTest`
(transform, pan, zoom around the cursor, fit, grid step, hit tests, whole-block drag, hatch and dash segments, the camera wedge,
items from the scene), `SyncTest` (manifest encode/decode and gzip, round trip of a project through the manifest, the push plan,
the record in `extra.syncmatica`), `ObjectTypesTest` (registry, bounds with transform and arrays, missing types, views, JSON round
trip), plus `ReconcileCoreTest` (cells ask their own derived file) and `FrontAndModifierTest` (arrays on external nodes).
