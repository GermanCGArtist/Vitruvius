# M5 test sheet: derived files, front-order trims, Boolean, Apply

Needs the game (nothing here is covered by unit tests; MaskPlan, PlacedGrid and the reconciler switch are).
Use a project with at least two overlapping schematic objects.

1. Trims: put object A (front P1) over object B (P2) so their boxes overlap. Within about a second the status bar shows
   "Rebuilding 1 derived file..." and B loses the blocks A has there. Check `Projects/<name>/.cache/derived/<B id>-<hash>.litematic` exists.
   A partly empty A trims B only where A has blocks.
2. Overlap volumes: red translucent volume with hatch on the top face; select A or B: label "-N blocks from B". The Scene
   Issues chip lists the objects that lose blocks, sorted by front. Tree row shows "-N" and Properties > Blocks shows the removed count.
3. Front order: Front/Back/up/down on A swaps who loses; derived files rebuild. Dragging with the gizmo: nothing rebuilds until release.
4. Boolean: select B, + Boolean, pick a cutter with the dropdown, or arm the eyedropper (crosshair, hint "pick the cutter") and
   click an object in the world; Esc or right click cancels. Status line: "Removes ~N blocks" or the warning
   "The cutter doesn't touch this object". The toggle off removes the cut (file switches back). Intersect keeps only the cutter's blocks.
5. "Draw cutter as wire": the cutter becomes a dotted violet outline, its own placement is hidden; un-wire from the Cutter section.
6. Apply: with a ready cut click "Apply -> new .litematic" (or the menu entry); the object points at `files/<name>_bool.litematic`,
   the Boolean is gone. Ctrl Z restores the old file and the modifier; the copy moves to `.trash`. Apply right after adding the Boolean builds first ("Building...").
7. Material list (Litematica M, placement of a trimmed object): counts exclude the trimmed blocks. Litematica's MaterialListPlacement runs
   TaskCountBlocksPlacement, which reads the WorldSchematic built from the placement's schematic file, which is the derived file.
8. Exports: "Export as .litematic" on a trimmed or Booleaned object writes the derived variant; Bake uses ready derived files for base cells.
9. Cleanup: change a cutter, save the project (Ctrl S); old derived files appear under `.trash/derived`, nothing is deleted.

Known limits: array cells and Loose objects and parts of linked assemblies are not trimmed (only the base cell of project objects).
